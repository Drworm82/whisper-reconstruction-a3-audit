# POC 5 — Scheduler + whisper-server Integration Results

**Date:** 2026-09-09  
**Branch:** `reconstruction-fixes`

## Objective

Validate the integration path from scheduler-generated overlapping WAV windows through persistent `whisper-server`, the whisper-server JSON adapter, word construction, and the existing reconstruction path.

This POC does not yet validate a live bounded inference queue or end-to-end real-time latency.

## Test configuration

Scheduler windows generated by POC4:

- Window 0: `0-5s`
- Window 1: `4-9s`
- Window 2: `8-13s`
- Window duration: `5s`
- Overlap: `1s`
- Step: `4s`

The WAV files were processed sequentially through the persistent whisper-server instance using `verbose_json` responses.

The resulting JSON was converted with `Convert-WhisperServer` and then passed through `Build-WhisperWords`.

For reconstruction testing, each window's ASR-relative timestamps were translated to the scheduler's global timeline by adding the corresponding window start (`0`, `4`, and `8` seconds).

## Interpretation

### PASS — structural integration

The following path operated successfully on real scheduler-generated WAV files:

```text
WASAPI loopback scheduler
    -> scheduler WAV windows
    -> whisper-server
    -> Convert-WhisperServer
    -> Build-WhisperWords
    -> Reconstruct-WhisperWindows
```

No words were lost by count comparison, no reconstructed IDs were duplicated, and the final sequence remained temporally ordered.

### MATCH/deduplication remains unvalidated by this sample

Both reconstruction transitions returned `SIN MATCH`. This is consistent with the actual ASR output in these windows rather than evidence of a reconstruction defect.

For the `0-5s` → `4-9s` transition, the `4-5s` overlap did not contain sufficient lexical content common to both ASR results to form a match. Window 0 contained a `♪` unit in that interval, while window 1 began with punctuation and `upbeat`.

For the `4-9s` → `8-13s` transition, window 1's recognized content ended at approximately `6.57s`, so there was no lexical content from window 1 in the `8-9s` physical overlap region.

Therefore this POC validates preservation and ordering through the reconstruction path, but it does **not** validate successful deduplication of genuinely repeated speech across overlapping ASR windows.

No reconstruction code should be changed solely because these transitions returned `SIN MATCH`.

## Limitations

- The scheduler is still an isolated POC rather than the final production capture/inference orchestrator.
- Inference was performed sequentially against already-created WAV files rather than through the final bounded inference queue.
- No end-to-end capture-to-transcript latency was measured.
- No GPU failure/watchdog behavior was tested here.
- No queue overflow policy was tested here.
- No device-change/reconnection behavior was tested here.
- No long-duration soak test was performed.
- The current audio sample did not provide lexical repetition across the physical overlap regions, so MATCH/deduplication remains a separate validation requirement.

## Status

**POC5 structural integration: PASS.**

**Real overlap MATCH/deduplication validation: NOT YET VALIDATED.**

The next implementation/validation step is bounded inference-queue integration, while keeping watchdog, overflow policy, latency, device-change behavior, and long-duration soak testing as separate concerns.
